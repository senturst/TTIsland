# 计划书：P6 内容扩展 与 P7 角色成长系统

> 本文档承接《孤岛残响》已完成的首版闭环（P0 骨架 + P1 单机闭环 + P1.5 AI 风味）
> 以及已实现的 P3（世界事件播报）、P4（墓碑交织）、P5（排行榜）。
> 目标：在**不破坏既有平衡立场**的前提下，把游戏从「5 层刷装备」扩成「多地区世界」，
> 并补上「本局内成长」这最后一块体验拼图。

---

## 0. 不可动摇的平衡立场（所有设计的边界）

这些是从首版设计里沉淀下来的硬约束，P6/P7 的任何方案都不能绕过：

1. **通关必须优于死亡**——撤离带回满耐久遗物 + 不涨传承 + 撤离津贴 + 无墓碑；
   死亡留衰减装备散给他人。否则「干脆早死」会变成最优解，难度曲线被架空。
2. **防滚雪球靠机制而非数值**——装备两路流入（遗物继承、墓碑搜刮）都受
   `tier≤2` + 衰减上限（3 代）约束，且**遗物不进墓碑池**（防一件装备拿两次）。
3. **天赋是死亡补偿，不是成长系统**——只在本局生效；撤离成功后不触发。
4. **撤离率锚定 ~10%**——整局送达率不应被调到「更友好」，多周目循环靠刷取缩短运气方差，
   但第二轮在同等强度下**永远有翻车可能**。所有数值调整走 `scripts/sim.py` 模拟校准，不凭感觉。

P7 的成长系统（用户已确认）是**本局内加点**：只在单次下潜中成长，死亡清零，
与「遗物/墓碑的跨周目循环」互补，而不是架空第 3 条。

## P6：内容扩展

### P6.1 目标
从「单一地区 5 层」扩成「多地区世界地图」，并显著丰富可玩内容密度。
让多周目不再只是反复刷同一 5 层，而是有新的地图、敌人、装备与抉择。

### P6.2 范围拆分

#### P6.2.1 突破 5 层上限（世界地图 / 地区系统）
- 新增 `configs/regions.yaml`（或扩展现有 `level_themes.yaml`）定义**地区**结构：
  每个地区含若干层（默认 5 层），有自己的主题、敌人权重、掉落表、机制。
- `max_level` 改为「当前地区层数」，世界地图在玩家**撤离某地区**后解锁下一地区入口。
- 跨地区进度用一个轻量 `player.region_progress`（已撤离地区最高层数）持久化。
- **关键平衡**：每个地区独立套用「每层通过率」模型（88/76/65/55/45 → ~10.8% 该地区撤离率）。
  多地区是**串联**而非并联：整局撤离率 = 各地区撤离率连乘，越往后越难，
  但单地区仍可刷装备强化自己再去挑战——这正是「反复刷地区 1 攒装备 → 打地区 2」的设计意图。

#### P6.2.2 更丰富的场景（房间类型扩展）
- 现在房间类型有限（战斗/搜刮/休息/墓碑/ stairs）。新增：
  - **环境灾害房**（毒气/塌方）：限时抉择，考验已有权衡机制。
  - **商人/NPC 残存点**：用「人道主义点数」或 scav 资源兑换，强化「人道 vs 自利」张力。
  - **变异巢穴（Boss 前置）**：地区第 5 层固定为地区 Boss，击杀掉落该地区专属遗物。
- 每个新房型走现有 `room_template` 配置 + `level_rules.can_*` 门控，不碰核心战斗。

#### P6.2.3 更多武器装备
- 现有 `items.yaml` 已有武器/护甲/消耗品/弹药/材料/纪念品框架。
- 扩展方向（保持 tier 分层，重火力 tier>2 不进墓碑池）：
  - 近战：撬棍 → 砍刀 → 消防斧（tier2 上限，不进墓碑）
  - 远程：手枪 → 霰弹枪（tier2）→ 自动武器
  - 护甲：布甲 → 皮夹克 → 防爆服
  - 消耗品：现有绷带/罐头基础上加 **可注射强化剂**（短时 buff，与天赋/成长形成组合）
- 新增物品一律先在 `sim.py` 跑平衡（单件强度不破坏 10% 撤离率锚点）。

#### P6.2.4 更丰富的敌人
- `monsters.yaml` 增加地区专属敌人 + 地区 Boss（带独特机制，复用现有 `combat.make_enemy` 与 Boss 引开机制）。
- 敌人强度随深度缩放，沿用现有 `make_enemy(depth)`。

### P6.3 验收标准
- [ ] 世界地图可显示已解锁地区与当前所在地区。
- [ ] 撤离地区 1 后，地区 2 入口在下一局可选（或自动进入更深）。
- [ ] 每层通过率经 `sim.py -n 300` 校准仍在目标区间，整局撤离率 ~10%。
- [ ] 新增房型/敌人/物品进入 `sim.py` 与手动试玩，无破坏平衡的数值漂移。
- [ ] 遗物继承 / 墓碑池的 tier 上限约束对新地区物品同样生效（不漏新重火力）。

### P6.4 风险与耦合
- **风险**：内容爆炸式增长会让 `sim.py` 校准成本上升。缓解：新增内容先配数值骨架，
  再批量跑模拟器，按输出反推数值，而非反过来。
- **耦合**：世界地图必须复用 P4 墓碑的 tier/衰减约束（新房型掉落也走 `legacy_allowed`）。
- **复用**：P3 的 SSE 事件通道可直接广播「新地区解锁」「首杀 Boss」等里程碑事件。

## P7：角色成长系统（本局内升级加点）

### P7.1 目标
在**单局内**提供「战斗升级 + 加点」的成长反馈，让单局过程有 RPG 厚度；
死亡清零，不与「跨周目刷装备」的永久循环冲突（已与用户确认：本局加点）。

### P7.2 设计原则（与平衡立场对齐）
- **本局内有效，死亡清零**：加点存在 `run_state` 里，不写 `players` 表（只有 `best_*` 统计保留）。
- **不与遗物/天赋叠加成「稳过」**：加点提供中等增益（对标天赋量级，+0.05~+0.30 层等效），
  且**不解锁新机制**，只是强化已有维度（伤害/血量/感染抗性/噪音控制）。
- **成长来自「击杀/探索」而非「刷怪」**：击杀给 XP，XP 满升级给 1 点可分配属性点，
  玩家在升级瞬间三选一加点（复用天赋的「三选一」UI 范式，降低前端成本）。

### P7.3 具体方案

#### P7.3.1 经验与升级
- 击杀按怪物强度给 XP（`combat` 结算处累加）；搜刮/事件也给少量 XP。
- XP 阈值用 `balance.yaml` 配置（例如每级线性+小幅曲线）。
- 升级时 `pending_decision = "levelup"`，进入三选一加点（**不阻断**当前回合节奏太多，
  但提供明确的成长峰值）。

#### P7.3.2 加点维度（4 选 1 每级给 1 点，三选一呈现）
| 维度 | 效果 | 量级 |
|---|---|---|
| 蛮力 | 近战/远程伤害 +% | 类似天赋 strength 档 |
| 坚韧 | 最大生命 + | 类似天赋 vitality 档 |
| 抗体 | 感染获取 -% | 复用药剂抗性逻辑 |
| 潜行 | 噪音生成 -% | 复用 noise 模块 |

- 加点效果在 `_sync_hp_max` / 战斗结算 / `noise.add` 处统一应用（与天赋同源，走 `talents.mod` 式查询）。
- **衰减约束**：加点增益**不继承**到遗物（遗物只来自通关/死亡时的装备），避免双重叠加滚雪球。

#### P7.3.3 与现有系统的边界
- **天赋**（死亡补偿）：进局时三选一，整局常驻。
- **加点**（本局成长）：局内击杀累积，升级时三选一，死亡清零。
- 二者**不互斥**但**量级隔离**：天赋是「入场补偿」，加点是「局内成长」，
  都受 +0.05~+0.30 层等效的审计约束（复用 `sim.py --talents` 改造为 `--growth` 审计）。

### P7.4 验收标准
- [ ] 击杀累积 XP，满级触发三选一加点 UI，加点即时生效。
- [ ] 死亡后加点清零，下一局不残留。
- [ ] 加点增益经 `sim.py --growth` 审计，单维度强度落在 +0.05~+0.30 层等效区间。
- [ ] 加点不破坏 10% 撤离率锚点（与天赋增益叠加后整局仍 ~10%）。
- [ ] 加点效果不泄漏进遗物继承通道。

### P7.5 风险与耦合
- **风险**：加点 + 天赋 + 遗物三路增益叠加可能悄悄抬高撤离率。
  缓解：所有增益集中走一个 `effective_mods(state)` 聚合函数，`sim.py` 对该函数做端到端审计。
- **复用**：三选一 UI 直接复用天赋的 `pending_decision` + available_actions 范式，前端零新增范式。

## 实施顺序建议（回顾）

P3（事件播报）→ P4（墓碑）→ P5（排行）已完成。
下一步建议 **P6 先行**（内容扩展是留存的骨架），**P7 收尾**
（成长系统是体验放大器，且其增益审计依赖 P6 已稳定的平衡基线）。
P7 与既有平衡立场耦合最紧，开工前用 `sim.py` 先把「天赋+加点」叠加模型跑通。

## 待用户拍板的开放问题
1. 世界地图的「地区切换」交互：是「撤离后下一局自动进更深地区」，
   还是「主菜单手动选择已解锁地区」？（影响 P6.2.1 的持久化与入口设计）
2. P7 升级三选一的触发频率：每局大约期望升几级？（影响 XP 曲线与单局时长）
3. 新增房型（商人/NPC）是否引入**软货币**（人道点数之外的第二种资源）？
   还是完全复用现有人道点数？
