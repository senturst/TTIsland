# 孤岛残响

末世僵尸题材的文字 Roguelike 网页游戏。

玩家扮演幸存者，逐层下潜探索随机生成的地图，与感染者回合制战斗、搜刮物资、
管理感染与噪音，最终在第五层登上直升机——或者倒在半路上。

**这不是"通关一次就毕业"的游戏。** 这五层是**地区 1**，整局撤离率约 10%，
设计目标是反复游玩：刷装备、攒实力，然后去挑战后续地区。

## 快速开始

```bash
# 1. 安装依赖（首次）
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
# .venv/bin/python -m pip install -r requirements.txt         # macOS / Linux

# 2. 配置（可选）
cp .env.example .env      # 填 LLM_API_KEY 可启用 AI 风味文本；不填也能玩

# 3. 启动
python scripts/restart.py          # 后台启动，日志写 logs/server.log
python scripts/restart.py --fg     # 前台启动，直接看日志
python scripts/restart.py --stop   # 停止
```

打开 http://127.0.0.1:8000 即可游玩。

> **为什么用 `scripts/restart.py` 而不是直接跑 uvicorn**
> 直接跑 uvicorn 时，上一轮进程经常没被真正杀掉、端口仍被占用，
> 新进程启动失败而你以为"改动没生效"——实际跑的还是旧代码。
> 这个脚本会按端口精确清理、校验配置、再启动，省掉这类十分钟起步的排查。

## 推送到 GitHub

```bash
python scripts/push_github.py --check   # 先验权限，比推失败再排查快
python scripts/push_github.py          # 推送当前分支
```

token 放在 `.env` 的 `GITHUB_TOKEN=`（该文件已被 gitignore），
脚本只在本次推送时拼接 URL，不会把凭据写进 `.git/config`，输出里也会屏蔽它。

> **403 Permission denied 的坑**：fine-grained token 创建时默认是
> `Public repositories (read-only)`——即使仓库是你自己的，push 也会被拒。
> 需要改成 `Only select repositories → 勾选本仓库` +
> `Contents: Read and write`。或直接用 classic token 勾 `repo` 范围。

## 玩法要点

| 系统 | 说明 |
|---|---|
| **感染度 0-100** | 75+ 给的是**增益**而非惩罚（伤害 +20%），高感染是一种可玩的策略位置 |
| **噪音 0-10** | 枪强但吵，近战弱但安静。越过阈值触发尸潮，本层僵尸密度翻倍 |
| **五层主题** | 日光 → 手电电量 → 高危污染区 → 警报系统 → 撤离倒计时。数值只涨 8%/层，难度靠机制 |
| **天赋三选一** | **复活进场**时抽三个选一个（上一局撤离成功则不触发）。定位是死亡补偿，只在本局生效 |
| **遗物继承** | 死亡或撤离时留一件给下一个角色。撤离带回的是**满耐久、不涨传承次数**的；死亡的是**衰减过的** |
| **重火力带不走** | tier 3（消防斧 / 霰弹枪）不可继承，且传承满 3 代报废——这是防滚雪球的核心 |

### 为什么撤离比死亡划算

如果两者代价一样，最优解会变成"反正装备都要丢，不如早点死"，
难度曲线会被这个策略架空。所以：

- **撤离** = 装备保养好带回家（耐久全满、传承次数不变）+ 撤离津贴，且**不产生墓碑**
- **死亡** = 从尸体上扒回来的（耐久衰减、传承次数 +1），其余装备散落进墓碑池**给别人摸**

## 玩法说明

（上面是速查表，这里讲完整玩法。）

### 目标与核心循环

你是一名幸存者，目标是从地表逐层下潜，在**第五层**登上直升机撤离。
这五层只是**地区 1**，整局撤离率约 10%——设计上鼓励反复游玩：刷装备、攒实力，
再去挑战后续地区。每一局都是独立下潜，死亡或撤离后带着遗物进入下一局。

### 开局

- **天赋三选一**：复活进场时从三个随机天赋里选一个（上一局**撤离成功**则不触发）。
  天赋是**死亡补偿**，只在本局生效。
- **自定名字**：开局可取名，名字会经过内容审核（违法 / 不雅会被拒），通过后记入排行榜。
- **命名审核**：服务端用规则 + 可选 AI 双重过滤，客户端无法绕过（见下方「防作弊」）。

### 探索与房间

每层是随机生成的有向图房间。房间有不同模板（战斗、搜刮、事件、楼梯、篝火…）。
搜刮可能找到武器、护甲、消耗品、材料、现金或废料。

### 战斗

- **近战 / 射击**：命令区按当前武器给出「攻击」或「射击」。命中由武器命中修正、远程天赋、
  以及 buff 决定，**与体力无关**（低体力只是用不了瞄准，绝不降低基础命中）。
- **瞄准（免费预备动作）**：消耗体力换取数回合的命中加成，**不占用回合**——
  瞄准后敌人不会获得一次行动，你可以接着攻击 / 射击。瞄准是刷新而非叠加，
  反复瞄准不会无限堆命中。
- **体力**：冲刺逃跑、瞄准消耗体力；罐头 / 能量饮料 / 篝火回体力。体力是真实资源，HUD 有独立体力条。
- **逃跑**：冲刺脱离战斗，消耗体力，但仍有风险。

### 感染度与尸化

感染 0–100。**75+ 给的是增益而非惩罚**（伤害 +20%），高感染是一种可玩的策略位置。
到 100 会触发**尸化**抉择：你可以现在放弃，或者索性随它去（变成感染体继续）。
死亡 / 尸化都会留下墓碑。

### 噪音与尸潮

噪音 0–10。枪械强但吵，近战弱但安静。越过阈值触发**尸潮**，本层僵尸密度翻倍。
管理噪音是高层生存的关键。

### 背包与容量

- 背包有格子上限（`balance.player.bag_slots`），部分护甲带**口袋**额外扩容。
- 拾取超过容量会暂停让你**丢掉一件腾位**或放弃新物；换上更小背包导致溢出时也必须丢弃到装得下。
- 武器 / 护甲可装备；装备也占对应栏位。

### 货币：废料与现金

两类硬通货：

- **废料（scrap）**：近战修理的主要耗材。
- **现金（cash）**：商人购买、作者怜悯用现金；卖东西换现金。
- 弹药、消耗品、现金本身**不可卖**。

### 商人

房间可能刷出商人，随机铺货。面板里可：

- **购买（现金）/ 作者怜悯（现金）**：困难时打折甚至白送。
- **修理**：武器 / 护甲可用**废料**或**现金**修复耐久（按 tier 计价）。
- **出售**：把纪念品等换成现金。
- **感染商人 / 作者怜悯**：高感染或濒死时的特殊交互。

### 遗物继承（软 Roguelite）

死亡或撤离时留**一件**遗物给下一个角色：

- **撤离**带回的是满耐久、不涨传承次数的；且**不产生墓碑**。
- **死亡**的是衰减过的，且其余装备散进**墓碑池**给别人摸。
- **重火力带不走**：tier 3（消防斧 / 霰弹枪）不可继承，且传承满 3 代报废——这是防滚雪球的核心。

### 墓碑

死亡的玩家遗体会出现在**别人**的地图里，可搜刮，但每次只能取走上面的一件道具；
原主人会收到「你的遗体被某人发现了」回执。

### 防作弊（服务器权威）

- 玩家**只能发送意图**（`action` + `payload`），全部规则在服务端结算；
  客户端**无法直接写** hp / 物品 / 货币——想改状态只能走受令牌保护的管理后台。
- 命名经过服务端审核，客户端无法用 `/rename` 绕过设任意名字。
- 管理后台所有接口要求登录会话，未登录一律 401；令牌弱口令 / 未配置时拒绝登录。

## 调平衡

数值全在 `configs/`，改完**不用重启**（配置热重载）。

```bash
python scripts/sim.py -n 300              # 各层通过率 vs 目标
python scripts/sim.py --talents -n 660    # 逐条测量每个天赋的强度
python scripts/sim.py --chain 4           # 验证遗物继承没有滚雪球
python tests/test_cache_deadlock.py       # 回归测试
```

目标值写在 `configs/balance.yaml` 的 `targets` 段：

| 层 | 目标通过率 |
|---|---|
| 1 | 88% |
| 2 | 76% |
| 3 | 65% |
| 4 | 55% |
| 5 | 45% |

连乘 ≈ 10.8%，即**平均十局撤离一次**。

### 热重载的边界

- **纯数值**（`balance.yaml`）—— 随时改，即时生效
- **提示词模板** —— 版本号写在缓存键里，改了自动失效
- **结构配置**（增删物品/怪物/天赋 ID）—— 需要重启。删除 ID 会让正在进行的 run 崩溃，
  系统会**拒绝**这类热重载并提示原因
- **Python 代码** —— 用 `scripts/restart.py --reload`

## AI 风味文本（可选）

不配 Key 也能完整游玩，只是文字用内置模板。配置后 AI 会生成：
房间氛围、遭遇开场白、物品描述、墓志铭、死亡旁白。

设计上保证 AI **永不阻塞操作**：

- 装饰性文本先返回模板立即渲染，AI 生成后随下一次响应作为 patch 原地替换
- 缓存键用粗粒度变量（房间氛围只用"房间模板 + 层数"），稳态命中率 >95%
- 四级降级：缓存命中 → 模板兜底 → 熔断 → 日预算耗尽
- 输出强校验：超长 / 含换行 / 含 Markdown / 非中文一律判非法并降级

成本上限在 `.env` 的 `LLM_DAILY_BUDGET_CENTS`。

## 管理后台

运营者用的内部页面，访问 `/admin`：

1. **登录**：口令来自配置文件——环境变量 `ADMIN_TOKEN`（写在 `.env`，已被 gitignore）优先，
   否则 `configs/admin.yaml` 的 `token`。**未配置或仍是默认弱口令时拒绝登录**（启动会打印告警）。
2. **配置管理**：列出并直接编辑 `configs/` 下所有 YAML（令牌文件 `admin.yaml` 不在可编辑列表）。
   保存即触发热重载；若新配置不合法，自动回滚到上一版并提示原因，**绝不让坏配置挂掉服务**。
3. **玩家管理**：列出所有「存活在玩」的玩家（含层 / HP / 感染 / 战斗 / 分数），
   点开可查看并修改其**完整状态与道具**（`inventory` / `weapon` / `armor` / `cash` / `scrap` 等）。
   保存后玩家下次行动会加载这份状态。

> 安全提示：管理后台是高权限入口，请务必设置强随机令牌（`openssl rand -hex 24`），
> 不要暴露到公网，也不要提交含明文口令的 `configs/admin.yaml`（该文件已在 `.gitignore`）。
